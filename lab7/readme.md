# PA7. Безопасность распределённой системы

Реализация на основе `lab6`: сохранены сегментирование Redis по странам, RabbitMQ, журнал событий, SignalR и запуск нескольких экземпляров компонентов.

## Запуск

```bash
cd lab7
docker compose up --build -d
```

Приложение: http://localhost:8080. Сначала зарегистрируйтесь или войдите, затем отправьте текст и выберите страну. После регистрации вход выполняется автоматически. Выход доступен кнопкой в меню.

RabbitMQ Management: http://localhost:15672. Логин и пароль берутся из `.env`.

Файл `.env` содержит **только пароли локального окружения разработчика**. Docker Compose передаёт их компонентам через переменные окружения. Для другого окружения задайте собственные значения `REDIS_PASSWORD`, `RABBITMQ_USER`, `RABBITMQ_PASSWORD`. Паролей и запасных паролей в коде приложений нет; отсутствие пароля приводит к ошибке конфигурации.

Для нескольких экземпляров:

```bash
./scripts/valuator_up 3 4
```

## Защита промежуточного ПО

Все четыре Redis запускаются с `requirepass`. Веб-приложение и обработчик рейтинга используют `REDIS_PASSWORD` при подключении к основной БД и каждому сегменту. RabbitMQ создаёт пользователя из `RABBITMQ_DEFAULT_USER` и `RABBITMQ_DEFAULT_PASS`; все три компонента подключаются с `RABBITMQ_USER` и `RABBITMQ_PASSWORD`.

| Переменная | Назначение | Значение вне Docker по умолчанию |
| --- | --- | --- |
| `DB_MAIN` | Основная БД: карта сегментов и пользователи | `localhost:6000` |
| `DB_RU` | Russia | `localhost:6001` |
| `DB_EU` | France, Germany | `localhost:6002` |
| `DB_ASIA` | UAE, India | `localhost:6003` |
| `REDIS_PASSWORD` | Пароль всех Redis | Обязательна |
| `RABBITMQ_HOST` | Адрес брокера | `localhost` |
| `RABBITMQ_USER` | Логин брокера | `guest` |
| `RABBITMQ_PASSWORD` | Пароль брокера | Обязательна |
| `DATA_PROTECTION_PATH` | Общие ключи шифрования cookie | Каталог `keys` приложения |

## Пользователи и доступ к результатам

Логин содержит 3–64 латинских буквы, цифры, `_` или `-`. Уникальность не зависит от регистра: `Alice` и `alice` — один логин. Регистрация использует атомарную запись Redis `SET NX`, поэтому параллельные запросы на разных экземплярах не создают одинаковые логины. Пароль содержит 8–128 символов.

В основной БД ключ `USER-{нормализованный логин}` хранит ID, логин и хеш пароля. `PasswordHasher` ASP.NET Core создаёт PBKDF2-хеш с индивидуальной солью. Открытые пароли пользователей не сохраняются. Вход выдаёт зашифрованную cookie с `HttpOnly`, `SameSite=Strict` и сроком действия 8 часов со скользящим продлением. Cookie содержит claims `NameIdentifier` и `Name`. Ключи Data Protection общие для всех экземпляров веб-приложения. Формы используют встроенную защиту Razor Pages от CSRF; выход выполняется POST-запросом.

В сегменте вместе с `TEXT-{id}`, `COUNTRY-{id}`, `SIMILARITY-{id}`, `RANK-{id}` сохраняется `AUTHOR-{id}` с ID текущего пользователя. Автор определяется сервером по cookie. Основная БД по-прежнему хранит карту `SHARD-{id}`.

Отправка текста, страница Summary и SignalR требуют входа. Summary проверяет автора до чтения результатов и возвращает `404` для чужого, отсутствующего или некорректного ID. Ответы Summary запрещено кешировать. SignalR проверяет автора до добавления подключения в группу и отправки рейтинга; анонимное подключение получает `401`. Тексты без автора недоступны через Summary и SignalR. Сравнение на плагиат, как в lab6, выполняется сервером по всем текстам.

Все Redis используют AOF и отдельные именованные тома; пользователи, тексты и результаты сохраняются после пересоздания контейнеров.

## Проверка

Автоматическая интеграционная проверка использует Python 3 без дополнительных пакетов и работающий стенд:

```bash
python3 scripts/security_check.py
```

Она проверяет пароли всех Redis и RabbitMQ, регистрацию, уникальность логина без учёта регистра, отказ при неверном пароле, вход и выход, обработку текста, доступ автора к Summary, отказ другому пользователю и анониму, а также авторизацию подписок SignalR. При каждом запуске создаются две тестовые учётные записи и один текст. Для другого имени проекта Compose задайте `COMPOSE_PROJECT_NAME`; для других адресов — `BASE_URL` и `RABBITMQ_URL`.

Ручная проверка Redis:

```bash
docker compose exec redis-main redis-cli PING
docker compose exec redis-main sh -c 'REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli PING'
docker compose exec redis-eu sh -c 'REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli --scan --pattern "AUTHOR-*"'
```

Первый запрос возвращает `NOAUTH`, второй — `PONG`, третий показывает записи авторов текстов из сегмента EU. Для проверки браузером создайте два аккаунта в разных профилях: ссылка Summary первого аккаунта должна возвращать `404` во втором, а после выхода перенаправлять на вход.

Остановка с сохранением данных:

```bash
docker compose down
```
